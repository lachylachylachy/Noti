# UI Language

## Overall Direction

Noti should feel like a calm glass workspace floating over the desktop.

The visual language should be:

- dark
- glassy
- soft
- spacious
- minimal
- premium
- macOS-inspired
- restrained

Avoid blue-heavy gradients, overly colourful dashboards, harsh borders, and dense productivity clutter.

## Layout

The preferred layout is a single adaptive spatial workspace.

Core layout zones:

- minimal side rail
- contextual sidebar
- central workspace
- optional detail dock
- floating inline controls

These zones should feel layered, not boxed-in.

## Glass Rules

Glass should be used to create hierarchy, not decoration.

Use stronger glass for:

- main workspace
- primary panels
- active contextual surfaces

Use lighter/subtler glass for:

- inactive cards
- inline chips
- metadata
- secondary controls

Avoid stacking too many glass boxes inside each other.

If a section already sits inside a glass panel, its internal elements should usually be flatter and quieter.

## Typography

Typography should be clean and understated.

Use:

- larger, calm headings
- readable body text
- small metadata text
- clear spacing between hierarchy levels

Avoid:

- tiny dense tables
- overly bold UI labels
- excessive uppercase
- heavy metadata blocks

## Motion

Motion should feel smooth and spatial.

Good motion:

- panels gently fading/sliding in
- sidebars expanding contextually
- calendar weeks moving laterally
- workspace modes transitioning without hard cuts

Avoid:

- bouncy effects
- distracting animation
- excessive movement
- flashy transitions

## Sidebar Direction

The sidebar should not become a dense file tree or app launcher mess.

Preferred direction:

- minimal icon rail by default
- contextual expansion on interaction
- integrations as ecosystem bridges
- workspace-specific context when relevant

Examples:

- coding thread → repo/snippet context
- planning thread → reminders/calendar context
- project thread → board/project context

## Interaction Feel

Interactions should feel lightweight.

Prefer:

- inline editing
- hover controls
- subtle menus
- click-and-drag where natural
- optional contextual chips

Avoid heavy modal-first workflows unless absolutely necessary.
